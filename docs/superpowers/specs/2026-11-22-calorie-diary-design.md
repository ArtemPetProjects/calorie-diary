# Дизайн: Android-дневник калорий (BL-012)

Дата: 2026-11-22. Источник запроса: `E:\OpenCodeModel\Project_1\Проекты\Калькулятор калорий.md` и сообщение пользователя от 22.11.2026.

## Намерение

Лёгкое офлайн-приложение для телефона: заходишь — сразу открыт сегодняшний день, добавляешь продукт и вес — приложение считает калории и БЖУ и записывает их в полоски прогресса за день. Цели по калориям и БЖУ задаются во вкладке «Профиль». Это долгосрочный актив и портфолио-проект, не источник быстрых денег.

## Цели

- APK, который ставится на Android-телефон и работает полностью без сети.
- Локальная база продуктов с калорийностью и БЖУ на 100 г.
- Три вкладки: «День», «Продукты», «Профиль».
- Календарь: при запуске выбран сегодняшний день.
- Добавление записи: выбор/ввод продукта + вес в граммах → расчёт и запись в выбранный день.
- Четыре полоски прогресса за день: калории, белки, жиры, углеводы, относительно целей из профиля.
- Минимальный APK: без рекламы, аккаунтов, синхронизации и тяжёлых библиотек.

## Не цели

- Синхронизация, облако, экспорт, сканирование штрихкодов, рецепты, вес тела.
- Сложная анимация и «красивый» Material You ради вида.
- Релизная подпись: первым делом собирается отладочный APK, пригодный для установки.

## Антицели

- Требовать сеть, регистрацию или доступ к контактам.
- Раздувать APK и тормозить запуск.

## Ограничения

- Android Studio и Android SDK на ПК отсутствуют. Для сборки APK нужны command-line tools SDK; их установка в `E:\AndroidSdk` — системное изменение и требует отдельного подтверждения пользователя.
- Доступны Gradle 9.4.1, JDK 21, `https://dl.google.com/android/repository/...` (200) и Maven Central (200). Node.js отсутствует.
- Выбор здесь: `minSdk 24` (Android 7.0), `compileSdk/targetSdk 37`, Java 17, Kotlin со встроенной поддержкой AGP. Стабильные версии на 22.11.2026: AGP 9.5.2, Gradle 9.9.2, SDK platform 37 / build-tools 37.0.0. Отдельный Kotlin Gradle Plugin не нужен и запрещён AGP 9.
- Стек выбран мной из требования «максимально лёгкое и простое».

## Подходы

1. **Нативный Android на Kotlin, только платформенные View и SQLite (выбран).** Самый лёгкий APK, полная офлайн-работа, никаких лишних зависимостей. Цена — чуть больше ручного кода разметки.
2. Обёртка WebView вокруг HTML/JS. Интерфейс писать проще, но рантайм тяжелее, UX хуже, SDK всё равно нужен. Не подходит под «максимально лёгкое».
3. Flutter / React Native. Быстрая кроссплатформенность, но большой SDK и APK, а Node.js отсутствует. Отвергнуто.

## Решение

- Проект: `E:\Projects\CalorieDiary`, пакет `com.veles.caloriediary`, Gradle + Android Gradle Plugin 9.5.x.
- Хранилище: `SQLiteOpenHelper`, база `diary.db`, таблицы:
  - `products(_id, name UNIQUE, kcal, protein, fat, carbs)` — значения на 100 г;
  - `entries(_id, date TEXT YYYY-MM-DD, product_id, product_name, grams, kcal, protein, fat, carbs)` — имя и итог записаны снимком, чтобы правка или удаление продукта не меняли прошлое;
  - `targets(_id=1, kcal, protein, fat, carbs)` — цели пользователя.
- Вкладка «День»: шапка с месяцем и полоска из 7 дней (Пн–Вс), стрелки переключают неделю, `DatePickerDialog` — произвольный день; при запуске выбран сегодня. Ниже четыре полоски прогресса «текущее / цель» и кнопка «Добавить продукт». Диалог добавления: автодополнение по базе продуктов, поле веса в граммах, живой предпросмотр КБЖУ, сохранение в выбранный день. Если введённого продукта в базе нет, в том же диалоге предлагается создать его с КБЖУ на 100 г; продукт и приём пищи сохраняются одной операцией. Список записей дня с кнопкой удаления.
- Вкладка «Продукты»: поиск по названию, добавление продукта (название + КБЖУ на 100 г), редактирование и удаление любого продукта — стартового или своего. История дней не зависит от этих операций, потому что хранит снимок имени и итогов. Стартовый набор около 60 часто используемых продуктов с русскими названиями и примерными значениями, без внешнего датасета.
- Вкладка «Профиль»: четыре числовых поля целей (калории, белки, жиры, углеводы) и кнопка сохранения. Значения по умолчанию: 2000 ккал, 120/60/250 г.
- Расчёт вынесен в чистые функции `Calculation.kt`: `value = per100 * grams / 100`, округление до 1 знака; тесты на JVM без эмулятора.
- Интерфейс: обычные XML-разметки и строковые ресурсы на русском, без сетевого разрешения в манифесте.
- Сборка: `assembleDebug` → APK копируется в `E:\Projects\CalorieDiary\apk\CalorieDiary.apk`.

## Проверка

- JVM-юнит-тесты расчёта и суточных итогов: проходят.
- APK ставится на телефон пользователя, открывается без сети, сегодняшний день выбран, запись добавляется и удаляется, полоски меняются, цели сохраняются. Финальную проверку делает пользователь.

## Оставлено исполнителю

- Точная совместимость версий Gradle/AGP, конкретные значения стартового набора продуктов, мелкие детали вёрстки и форматирование даты.
