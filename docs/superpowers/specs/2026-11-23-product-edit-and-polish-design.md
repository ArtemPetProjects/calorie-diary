# Дизайн: редактирование продуктов/блюд, автокалории и визуальная доводка (BL-089–BL-096)

Дата: 2026-11-23. Источник: сообщения пользователя перед приёмкой дневника калорийности.

## Намерение

Сделать редактирование своих продуктов и блюд заметным, исключить рассинхрон калорийности и БЖУ в создаваемых продуктах, выделить недавние блюда, улучшить читаемость списков и подсказок, ускорить ввод в диалогах и показать процент выполнения в полосках БЖУ/калорий.

## Что найдено в базе

- Расширенный набор `products_extended.json`: 9140 позиций; 3354 (36,7%) отличаются от `4×Б + 9×Ж + 4×У` более чем на 5 ккал. Большинство — крупы, специи, орехи, сухофрукты: клетчатка учтена в углеводах, но не в усваиваемой калорийности. Пересчёт по 4/9/4 исказил бы эти значения.
- Стартовый набор `StarterProducts.kt`: 342 позиции; 110 расхождений. `Водка` = 235 ккал при нулевом БЖУ — энергия этанола (~7 ккал/г) в БЖУ не входит. В расширенном JSON та же «Водка» имеет 0 ккал, но при создании БД стартовый набор вставляется первым, а дубль имени игнорируется.
- Три позиции с нулевым БЖУ и 0,1–0,2 ккал — округление.

**Решение пользователя:** ручной переопределённый kcal. Автоподстановка из БЖУ действует только для своих продуктов; введённая пользователем калорийность не перетирается. Готовую базу массово не пересчитываем; исправляем только `Водку` 0 ккал в JSON и три позиции с округлением до 0.

## Подходы и выбор

| Вопрос | Рассмотренные варианты | Выбор |
|---|---|---|
| Калории из БЖУ | Всегда пересчитывать / никогда не трогать / заполнять, пока пользователь не ввёл вручную | Третий: исключает опечатки и сохраняет алкоголь |
| Доступ к редактированию | Только тап по строке / явная кнопка в строке | Явная кнопка; тап оставляем |
| Недавние блюда | Отдельная таблица / уже существующая `product_usage` | `product_usage`: при добавлении блюда в день отмечается его id |
| Шрифт подсказок в блюде | Дублировать layout / задать размер в адаптере | Параметр адаптера, +1sp без второго layout |
| Красивее | Полная смена темы / точечная доводка | Точечная: карточки строк, отступы, заголовки, контраст |

## Решение по частям

1. **Редактирование (BL-089).** В `item_product.xml` добавляется кнопка «Изменить» рядом с удалением. Тап по строке и кнопка открывают те же диалоги: `ProductsView.showDialog(product)` для продукта и `DishDialog(dishId)` для блюда (уже сохраняют id, КБЖУ и итоговый вес).
2. **Автокалории (BL-090).** В `ProductsView.showDialog` и в блоке новых продуктов `DayView.showAddDialog` вешаем `TextWatcher` на белки/жиры/углеводы. Если все три поля заполнены и калорийность пуста либо была подставлена автоматически, вписываем `kcalFromMacros(...)`, округлённое до 1 знака. Ручной ввод калорий выключает автоподстановку до конца жизни диалога. При редактировании ручное значение сохраняется.
3. **Недавние блюда (BL-091).** `ProductsView.refreshList()` получает `db.recentProductIds()`; строки-блюда из этого набора красятся в светло-голубой (`#0288D1` в светлой теме, `#81D4FA` в тёмной — для контраста) через атрибут темы.
4. **Список ингредиентов (BL-092).** У `ingredientProduct` дропдаун сужается до ширины поля ввода (не шире окна диалога), шрифт подсказок становится 16/13sp вместо 15/12sp через параметр `SuggestionAdapter`.
5. **Клавиатура (BL-093).** Общий helper `focusAndShowKeyboard(dialog, field, selectAll)` вызывается в `OnShowListener` всех диалогов с полями: вес на дату, редактирование веса порции, создание/редактирование продукта, добавление продукта, конструктор блюда. Для числовых полей текст выделяется.
6. **Проценты в полосках (BL-094).** Чистая функция `progressPercent(current, target)` (0 при цели ≤ 0, иначе `current/target×100`, ограничение 0–100) покрывается тестом. Под полосой выводится «съедено / цель · N% · осталось X», где остаток не может быть отрицательным.
7. **Визуал (BL-095).** Скруглённые карточки для строк продуктов и записей еды, единые 12dp отступы, чуть крупнее заголовки групп и второстепенный текст, видимый разделитель между строками. Цвета и токены остаются в `colors.xml`/`attrs.xml`.
8. **Аудит базы (BL-096).** В `products_extended.json`: «Водка» 0 → 235 ккал, три позиции с 0,1–0,2 ккал → 0. Остальные расхождения не трогаем: они объяснимы составом продуктов. Версия БД не меняется; на уже установленных устройствах данные остаются как есть.

## Проверка

- JVM-тесты: приоритет недавних, процент выполнения, калории из БЖУ и существующие регресс-тесты.
- `gradlew test assembleDebug` — код 0, все тесты зелёные; APK копируется в `apk/CalorieDiary.apk`.
- Ручной smoke: изменить продукт и блюдо; ввести БЖУ и убедиться, что калории подставились, а ручное значение не перетирается; проверить светло-голубые блюда, уже список ингредиентов, клавиатуру в каждом окне, проценты в полосках.

## Оставлено исполнителю

- Точные значения dp/sp и оттенок голубого уточняются при реализации в рамках заданных направлений.
- Новая схема БД не требуется; миграция не нужна.
