# Дизайн: встроенный выбор продукта, несколько черновиков блюд и обработка ошибок (BL-105–BL-108)

Дата: 2026-11-24. Источник: повторный отзыв пользователя после одиннадцатого APK.

## Намерение

Убрать наложение выпадающего списка на поле ввода, сделать список продуктов почти на всю ширину экрана, дать понятные сообщения об ошибках, разрешить создавать свой продукт из конструктора блюда, сделать двухстрочные подписи схем и хранить несколько поименованных черновиков блюд без потери.

## Причины, найденные разбором кода

- `AutoCompleteTextView` показывает подсказки во временном окне. При `SOFT_INPUT_ADJUST_RESIZE` и появлении клавиатуры система переставляет это окно выше поля. Лечение — обычный `ListView` внутри разметки диалога.
- `dropDownWidth` считался от ширины поля и формально давал отступы; пользователь видит список на всю ширину. Лечение — `ListView` в `dialog_entry.xml` с шириной `match_parent` и горизонтальным padding диалога 2dp.
- В `DayView.showAddDialog` пустое имя и невалидный вес проверяются одним `if` с текстом «Укажите вес». Нужна раздельная проверка.
- `dish_drafts` имеет `profile_id PRIMARY KEY` — одна строка на профиль; имя блюда не сохраняется.

## Решение

1. **Встроенный список продуктов (BL-105).** В `dialog_entry.xml` добавить `ListView` под полем «Продукт». `SuggestionAdapter` подключается к нему, фильтруется по тексту. Клик по строке подставляет название и скрывает список. Поле ввода становится обычным `EditText`, а список — обычным `ListView` в разметке, поэтому наложение невозможно. Ширина — почти экран: горизонтальный padding содержимого диалога 2dp.
2. **Ошибки (BL-105).** Чистая функция `entryValidationError(name, grams): EntryError` с вариантами `NONE/NAME/WEIGHT` и тестами. Отдельные строки: «Введите название продукта», «Укажите вес». В каталоге продуктов — отдельные сообщения для пустого имени и пустой калорийности.
3. **Свой продукт из блюда (BL-106).** В каждой строке ингредиента кнопка «+» открывает компактный диалог создания продукта (название, калорийность, опциональные БЖУ) с уже работающей автоподстановкой калорий; после сохранения продукт добавляется в локальный список диалога и подставляется в ингредиент.
4. **Подписи схем (BL-107).** Отдельный layout `item_scheme.xml`: первая строка «Название — назначение», вторая «Б 15% / Ж 25% / У 60% — сбалансированное соотношение». Custom adapter в `ProfileView`, порядок совпадает с `MACRO_SCHEMES`.
5. **Несколько черновиков (BL-108).** Новая таблица `dish_drafts_v2(_id INTEGER PRIMARY KEY AUTOINCREMENT, profile_id INTEGER, name TEXT, items_json TEXT, created_at INTEGER)`. Миграция до версии 11 переносит старую единственную запись. Методы `saveDraft(name, items): Long`, `drafts(): List<DishDraft>`, `draft(id)`, `deleteDraft(id)`. Кнопка «Продолжить создание блюда» открывает диалог списка черновиков с именами; выбор открывает конструктор с загруженными названием и ингредиентами. При «Отложить» создаётся новая запись со введённым именем (если имя пустое — «Блюдо без названия N»). При «Сохранить» соответствующая запись удаляется.

## Проверка

- RED/GREEN-тесты для валидации, миграции черновиков и количества схем.
- `gradlew test assembleDebug`, код 0; APK распакован, JSON парсятся, миграция симулируется на копии БД.
- Ручная проверка на устройстве: ввод продукта без наложения списка, ширина с отступами, ошибки, создание продукта из блюда, два черновика и выбор нужного, сохранение названия, двухстрочные схемы.
