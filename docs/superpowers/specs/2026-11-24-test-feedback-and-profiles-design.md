# Дизайн: правки после теста APK и профили (BL-099, BL-100)

Дата: 2026-11-24. Источник: отзыв пользователя после девятого APK.

## Намерение

Устранить четыре дефекта, проявившиеся на телефоне, расширить белорусскую базу, изменить формат названий брендов, улучшить внешний вид и добавить несколько профилей с разными целями и схемами питания на одном устройстве.

## Причины, найденные разбором кода

1. **Клавиатура не появляется.** `Dialogs.focusAndShowKeyboard` вызывается из `OnShowListener`, выставляет `SOFT_INPUT_STATE_VISIBLE` после показа окна и не вызывает `InputMethodManager.showSoftInput`. Фокус ставится — поэтому курсор мигает, — но системная клавиатура не поднимается.
2. **Недавние продукты не голубые.** В `ProductsView` цвет присваивается только при `product.isDish && product.id in recentDishIds`. Обычные использованные продукты не попадают в условие.
3. **Нет молока Савушкина.** В ассете была только ряженка Савушкина и молоко «Молочной капельки»; искомой позиции физически нет. Поиск по `search_name` работает, но не находит несуществующего.
4. **Вес и калории в строке еды.** `DayView` собирает их в `entryText` вместе с названием: `${productName} • ${grams} г • ${kcal} ккал`, а БЖУ выводит во второй строке.

## Решение по дефектам

- **Клавиатура:** в `focusAndShowKeyboard` добавить `field.post { requestFocus(); InputMethodManager.showSoftInput(field, SHOW_IMPLICIT) }`; режим окна выставлять до `show()` там, где это возможно. Поведение проверяется на телефоне — автоматического теста Android IME нет.
- **Цвет:** убрать `product.isDish` из условия; голубым кодируется любой продукт, чей id есть в `recentProductIds()`. Цвет остаётся из атрибутов темы: `#0288D1` в светлой, `#81D4FA` в тёмной.
- **База:** расширить `products_belarus.json` минимум до 60 позиций. Найдены и добавляются с источниками: молоко 3,2% и 2,5% Савушкина, молоко 1/2,5/2,7/3,2/3,7% Молочный мир, молоко 3,2% Бабушкина крынка, сыры, сырки, твороги и йогурты этих брендов. Все названия приводятся к виду «Название (Бренд)». Реестр `docs/data/belarusian-products.csv` обновляется синхронно; тест читает оба файла и требует совпадения имён.
- **Оговорка про «все продукты»:** полный охват всего рынка гарантировать невозможно. Добавляются все позиции с полным КБЖУ, которые удаётся найти в доступных открытых источниках; позиции без полных данных не выдумываются. Новые источники можно добавлять отдельными партиями.
- **Строка еды:** первая строка — только название продукта; вторая — `вес • калории • Б/Ж/У`. Для этого добавляется строка `entry_details` и меняется сборка текста в `DayView`.
- **Пересчёт калорий:** пользователь уточнил 2026-11-24: при вводе каждого БЖУ-поля калории обновляются сразу, на каждый символ, в том числе при редактировании продукта. Прежнее правило «ручное значение не перетирается» заменено; исключение оставлено только для нулевого БЖУ при непустой калорийности (алкоголь).

## Стилизация

Ограниченный объём без смены темы:

- у групп приёмов пищи — четыре разных пастельных оттенка рамки/заголовка (завтрак, обед, ужин, перекус) через новые атрибуты темы;
- у полосок КБЖУ — цветная плашка-индикатор и подпись значения цветом соответствующего макроса;
- заголовки разделов 16sp полужирным, второстепенный текст 13sp с контрастным цветом;
- строки остаются скруглёнными карточками; отступы 12dp единообразны.

## Профили

**Выбор пользователя:** одна база, таблица `profiles`, `profile_id` в данных.

- `profiles (_id INTEGER PRIMARY KEY AUTOINCREMENT, name TEXT UNIQUE NOT NULL, body_kg REAL NOT NULL DEFAULT 0)`, при миграции создаётся профиль id=1 «Мой профиль», а вес тела переносится из старой настройки `body_weight` в `body_kg`.
- Активный профиль хранится в `SharedPreferences` под ключом `active_profile_id`.
- Разделяются по профилю: `entries`, `weights`, `targets`, `product_usage`, `dish_drafts` и вес тела в `profiles.body_kg`. Каталог продуктов и блюд остаётся общим.
- Технически: в `entries` добавляется колонка `profile_id`; таблицы `weights`, `targets`, `product_usage`, `dish_drafts` пересоздаются с составными ключами `(profile_id, ...)` и копированием существующих строк с `profile_id = 1`. Версия БД поднимается до 10; перед обновлением делается резервная копия.
- Все запросы (`entries`, `weightFor`, `targets`, `recentProductIds`, `markUsed`, черновик) фильтруются по активному профилю.
- В «Профиле» добавляется список профилей с кнопками «Добавить», «Переключить», «Переименовать», «Удалить». Удаление последнего профиля запрещено; удаление профиля с данными — только после подтверждения и с предупреждением, что его записи, вес и цели будут удалены.

## Дополнение пользователя 2026-11-24

1. **Пустой БЖУ при создании продукта.** Разрешить сохранять свой продукт, если заполнено только название и калорийность; пустые белки/жиры/углеводы сохраняются как нули. Ручная калорийность при этом не обнуляется, потому что все БЖУ нулевые. Запрет остаётся только на пустую калорийность.
2. **Профицит и дефицит.** На вкладке «День» добавляется поле со знаком: пользователь указывает, например, `+17` (недостаток со вчерашнего) или `-47` (переел вчера). Корректировка относится к выбранной дате и активному профилю, хранится отдельно и не меняет базовые цели. Дневная норма калорий увеличивается/уменьшается на эту величину, а целевые БЖУ пересчитываются пропорционально тому же коэффициенту. Чистая функция `adjustTargets(targets, delta)` покрывается тестом.
3. **Превышение в полосках.** Когда съедено больше цели, вместо «осталось 0» показывать «+X» избытка, а процент может быть больше 100. Чистая функция `remainingLabel(current, target)` возвращает «осталось X» или «+X» и покрывается тестом.

Эти три пункта добавляются в текущий план отдельными задачами до финальной сборки.
