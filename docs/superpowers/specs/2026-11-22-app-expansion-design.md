# Дизайн: расширение дневника калорий (BL-057–BL-062)

Дата: 2026-11-22. Источник: сообщение пользователя после подтверждения второго APK.

## Намерение

Сделать работу с продуктами и приёмами пищи информативнее: под выбранным продуктом сразу видны КБЖУ на 100 г; база продуктов становится в десятки раз больше; полоски толще; в списке съеденного есть БЖУ; записи группируются по времени приёма пищи; в профиле цели по БЖУ автоматически дают калории, а из калорий можно выбрать одну из пяти популярных схем.

## Цели

- Подсказка КБЖУ на 100 г под полем продукта в диалогах «Добавить продукт» и «Собрать блюдо».
- Офлайн-база 3000–10000 позиций с калорийностью и БЖУ на 100 г, включая русские названия и хурму.
- Более толстые и выразительные полоски, чуть улучшенные кнопки.
- БЖУ в каждой строке съеденного продукта.
- Группировка записей по времени: всё, записанное в течение часа, — один приём пищи.
- Профиль: калории считаются из БЖУ; при вводе калорий доступны пять схем БЖУ.

## Не цели

- Приложение без сети: все данные поставляются внутри APK.
- Автоматическое распознавание по фото (BL-054 остаётся «на подумать»).
- Изменение конструктора блюд и расчёта `dishPer100`.

## Ограничения и источники

- USDA SR Legacy CSV: `https://fdc.nal.usda.gov/fdc-datasets/FoodData_Central_sr_legacy_food_csv_2018-04.zip` (6 074 592 байт zip, ~7600 позиций), license CC0/public domain, БЖУ на 100 г, названия английские.
- Erech14 nutrition-table: `https://raw.githubusercontent.com/Erech14/nutrition-table/main/app/foods.csv` (90 291 байт, ~1109 позиций), русские названия, БЖУ на 100 г; `LICENSE` — MIT, в README — ограничение личными/некоммерческими целями; для личного приложения подходит, атрибуция в `NOTICE`.
- Схемы БЖУ: AMDR (белки 10–35%, жиры 20–35%, углеводы 45–65%) — NIH/PMC `https://pmc.ncbi.nlm.nih.gov/articles/PMC9206338/`; низкоуглеводные <25–30% углеводов, кето ≈70% калорий из жиров — `https://en.wikipedia.org/wiki/Low-carbohydrate_diet`. Пять схем ниже — моя интерпретация этих источников, не медицинская рекомендация.

## Подходы к базе

1. **Гибрид: текущие 342 русских + Erech14 (~1100 русских) + USDA SR Legacy (~7600 английских) (выбран).** Даёт ~9000 позиций и русские названия для повседневных продуктов. Минус: часть названий останется английской; дубли устранены по нормализованному имени.
2. Только USDA. Юридически чисто (CC0), но почти все названия английские — пользователь может не найти хурму.
3. Только Erech14. Русские названия, но «в десятки раз» не получается.
4. Open Food Facts. Русские имена частично есть, но полный дамп ~0,9 ГБ и лицензия ODbL с атрибуцией — слишком тяжело для APK.

## Решение

- Данные импортируются в `assets/products_extended.json`, при первом запуске/миграции вставляются в таблицу `products`. Версия БД 3.
- В `entries` добавляется `created_at INTEGER` (epoch ms). Старые записи получают 0 и показываются отдельной группой «Без времени».
- Чистые функции в `Calculation.kt` с JVM-тестами:
  - `kcalFromMacros(protein, fat, carbs): Double` = `p*4 + f*9 + c*4`, округление до 1 знака;
  - `gramsFromScheme(kcal, proteinPct, fatPct, carbsPct): Targets`;
  - `groupByMeal(entries, windowMs = 3_600_000): List<MealGroup>` — записи подряд попадают в одну группу, если разрыв от начала группы ≤ 1 часа.
- Пять схем в профиле (проценты от калорий): «Поддержание» 15/30/55, «Похудение» 28/27/45, «Набор мышц» 25/25/50, «Низкоуглеводная» 25/45/30, «Кето» 10/70/20. При выборе схемы поля БЖУ заполняются граммами, калории остаются введёнными.
- Профиль: при изменении БЖУ калории пересчитываются автоматически; при изменении калорий показывается ряд из пяти кнопок со схемами.
- Вкладка «День»: каждая строка съеденного показывает «продукт • вес • ккал • Б/Ж/У»; заголовок приёма показывает время и итог группы.
- Диалоги: под выбранным продуктом отдельная строка «ккал/Б/Ж/У на 100 г».
- Визуал: высота полосок ~14 dp вместо тонких, скруглённый фон и заполнение через `progressTint`; кнопки получают `StateListAnimator`/selector вместо плоского фона.

## Проверка

- JVM-тесты: `kcalFromMacros`, `gramsFromScheme`, `groupByMeal` (внутри часа, после часа, пустой список).
- `gradlew test assembleDebug` — код 0, все тесты зелёные, APK собирается.
- Ручной smoke: найти хурму, выбрать продукт и увидеть подсказку, добавить запись, увидеть БЖУ в списке, проверить две группы приёмов пищи, задать БЖУ в профиле и увидеть автокалории, выбрать схему по калориям, проверить толстые полоски и обе темы.

## Оставлено исполнителю

- Точная вёрстка новых строк и кнопок схем, форматирование percentages/граммов, порядок импорта данных и детали атрибуции в `NOTICE`.
