# Дизайн: UX дня, отказоустойчивость и безопасные обновления (BL-069–BL-074)

Дата: 2026-11-23. Источник: сообщение пользователя после четвёртого APK.

## Намерение

Сделать вкладку «День» информативнее и удобнее: показывать текущий вес тела, редактировать вес уже добавленных продуктов, структурировать приёмы пищи в сворачиваемые группы с рамкой. Повысить отказоустойчивость: резервные копии базы, сохранение данных при обновлении, понятные подсказки в автодополнении.

## Что уже есть

- История по дням хранится неограниченно в таблице `entries`; автоматической очистки нет.
- Цели — одна строка в `targets`; продукты и блюда — в `products`; вес тела — в `SharedPreferences`.
- БД версии 5; миграции делают `ALTER TABLE` и `CREATE TABLE IF NOT EXISTS`, не удаляя данные.
- Строки автодополнения — один `TextView` со всеми КБЖУ в одну строку, из-за чего они не вмещаются.
- Группы приёмов пищи уже считаются по часовому окну, но отображаются плоским списком.

## Цели

1. BL-069 — показывать сегодняшний вес тела во вкладке «День» (из профиля), при отсутствии — «—».
2. BL-070 — отказоустойчивость: копия БД перед миграцией и при запуске, хранение последних 3 копий, транзакции; обновление сохраняет продукты, записи, цели и настройки.
3. BL-071 — двухстрочный выпадающий список: название крупнее, КБЖУ на 100 г мельче под названием.
4. BL-072 — редактирование веса добавленной записи во вкладке «День» по нажатию на строку.
5. BL-073 — приоритет в подсказках: сначала продукты, имя которых начинается с введённого текста, затем остальные совпадения («слива» выше «булки со сливой»).
6. BL-074 — группы приёмов пищи с рамкой, заголовком и возможностью свернуть/развернуть; запоминать состояние в памяти экрана.

## Не цели

- Фото-распознавание (BL-054) и боты BL-063/BL-064.
- Облачная синхронизация и экспорт наружу.
- Изменение формул расчёта КБЖУ и `dishPer100`.

## Решение

- **Вес в «Дне»:** строка «Вес сегодня: 70,0 кг» под заголовком месяца; берётся из `SharedPreferences` ключа `body_weight`; обновляется при возврате на вкладку.
- **Резервные копии:** `Db` перед `onUpgrade` копирует `diary.db` в `files/backups/diary-<timestamp>.db`; при обычном запуске копия создаётся раз в сутки; хранятся последние 3. Копия — обычный файл приложения, доступный только приложению.
- **Обновление:** версия БД повышается только при изменении схемы; `onUpgrade` из версии 5 в 6 добавляет недостающие колонки/таблицы без `DROP`; тесты на вспомогательные функции миграции и ручная проверка на копии базы.
- **Подсказки:** новый `item_suggestion.xml` с двумя `TextView`; кастомный `RankedAdapter` с `Filter`, который сортирует кандидатов: `startsWith(query)` → `contains(query)`; имя продукта восстанавливается по разделителю.
- **Редактирование записи:** `Db.updateEntry(id, grams, values)`; в `DayView` нажатие на строку открывает диалог с весом, пересчитывает КБЖУ и сохраняет; кнопка удаления остаётся отдельной.
- **Группы:** вокруг заголовка и строк группы — `LinearLayout` с фоном-рамкой (`drawable/meal_group_border.xml`); клик по заголовку переключает видимость строк; состояние хранится в `MutableMap<Long, Boolean>` в `DayView`.

## Проверка

- JVM-тесты: ранжирование подсказок, пересчёт записи при изменении веса, `groupByMeal` без изменений.
- `gradlew test assembleDebug` — код 0, все тесты зелёные.
- Ручная проверка: выбрать «сли» → первым «Слива»; изменить вес записи; свернуть/развернуть приём; проверить вес в «Дне»; обновить APK и убедиться, что данные остались; проверить файлы backup в `files/backups`.

## Оставлено исполнителю

- Точные отступы/размеры текста подсказок и цвет рамки групп.
- Формат имени файла резервной копии и политика 3 копий.
